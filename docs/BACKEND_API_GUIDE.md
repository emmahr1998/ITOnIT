# ITOnIT Backend — API Guide

Endpoint-by-endpoint reference, generated by inspecting `app/api/routes/*.py`,
`app/services/*.py`, and `app/schemas/*.py` directly. For architecture background see
`docs/BACKEND_ARCHITECTURE.md`.

**Base response shapes used below:**
- **Wrapped** = `DataResponse[T]` (`app/schemas/response.py`): `{"data": T, "msg": "..."}`.
- **Bare** = the schema's fields directly, with no envelope.

Whether an endpoint is wrapped or bare is **not uniform across the API** — see
`docs/BACKEND_ARCHITECTURE.md` §19/22 for why. It is listed per-endpoint below.

---

## Health

### `GET /health`
File: `app/api/routes/health.py`. **Who can call it:** anyone (no auth). **Request:** none.
**DB action:** runs `SELECT 1` directly against the database. **Response (bare
`HealthResponse`):** `{"status": "healthy", "database": "connected", "version": "1.0.0"}`.
**Errors:** `503 Service Unavailable` if the `SELECT 1` raises `SQLAlchemyError` (DB
unreachable).

### `GET /`
File: `app/main.py`. **Who can call it:** anyone. Plain landing route, returns
`{"message": "Welcome to ITOnIT!"}`. Not part of `api_router` — declared directly on `app`.

## Authentication

### `POST /auth/login`
File: `app/api/routes/auth.py`, function `login`. **Who can call it:** anyone (no auth).
**Request body (`LoginRequest`):** `{"username": str, "password": str}` — `username` also
matches an existing user's `email` (Section 9 of the architecture doc). **Validation:**
Pydantic requires both fields present and non-empty-type-checked; no format restriction
beyond that. **Service call:** `AuthService.login(username, password)`. **Response (bare
`TokenResponse`, 200):** `{"access": "...", "refresh": "...", "token_type": "bearer"}`.
**Errors:** `401` `"Invalid username or password"` for unknown user, wrong password, or
inactive account (all three produce the identical message, by design).

### `POST /auth/refresh`
File: `app/api/routes/auth.py`, function `refresh`. **Who can call it:** anyone holding a
valid refresh token (no `Authorization` header needed — the refresh token is the credential,
sent in the body). **Request body (`RefreshRequest`):** `{"refresh": str}`. **Service call:**
`AuthService.refresh_access_token(refresh_token)`. **Response (bare `RefreshResponse`, 200):**
`{"access": "...", "token_type": "bearer"}`. **Errors:** `401`
`"Invalid or expired refresh token"` for a malformed/expired/wrong-type token, or a token
whose user no longer exists or is inactive.

### `GET /auth/me`
File: `app/api/routes/auth.py`, function `read_current_user`. **Who can call it:** any
authenticated user (`Depends(get_current_active_user)`). **Request:** none (just the
`Authorization` header). **Response (bare `CurrentUserResponse`, 200):** `id`, `email`,
`first_name`, `last_name`, `is_active`, `role` (resolved to the role's name string).
**Errors:** `401` if the token is missing/invalid/expired or the user is inactive.

## Departments

All routes: `app/api/routes/departments.py`. Every response is **wrapped**
(`DataResponse[DepartmentResponse]` or `DataResponse[list[DepartmentResponse]]`).

### `GET /departments`
**Who:** any authenticated user (`Depends(get_current_active_user)`). **Request:** none.
**Response (200):** `{"data": [DepartmentResponse, ...], "msg": "Departments list fetched successfully"}`.

### `POST /departments`
**Who:** Manager or Administrator (`require_roles("Manager", "Administrator")`).
**Request body (`DepartmentCreate`):** `{"title": str}` (1–100 chars, whitespace-stripped,
rejected if blank after stripping). **Response (201):** the created department, wrapped.
**Errors:** `409` `"A department with this title already exists"` (case-insensitive
uniqueness, checked both pre-emptively and via `IntegrityError` fallback in
`DepartmentService.create_department`); `403` if not Manager/Admin; `422` for a
missing/blank title.

### `GET /departments/{department_id}`
**Who:** any authenticated user. **Response (200):** the department, wrapped. **Errors:**
`404` `"Department not found"`.

### `PATCH /departments/{department_id}`
**Who:** Manager or Administrator. **Request body (`DepartmentUpdate`):** `{"title": str |
None}` — partial; omitting `title` is a no-op that still returns the unchanged department.
**Response (200):** the updated department, wrapped. **Errors:** `404` not found, `409`
title conflict.

*(No `DELETE /departments/{id}` exists — deliberately, by design of the current milestone.)*

## Priorities

All routes: `app/api/routes/priorities.py`. Structurally identical to Departments (same
service pattern: `PriorityService`, `app/services/priority_service.py`), one field renamed
(`title`, max 50 chars instead of 100).

- `GET /priorities` — any authenticated user, wrapped list.
- `POST /priorities` — Manager/Administrator, `{"title": str}`, `201`, `409` on duplicate.
- `GET /priorities/{priority_id}` — any authenticated user, `404` if missing.
- `PATCH /priorities/{priority_id}` — Manager/Administrator, partial update, `404`/`409`.

*(No `DELETE /priorities/{id}` exists.)*

## Locations

All routes: `app/api/routes/locations.py`. Service: `LocationService`
(`app/services/location_service.py`). Structurally similar to Departments/Priorities, with
two deliberate differences: an `is_active` field, and stricter write permissions.

### `GET /locations`
**Who:** any authenticated user (employees need to see the list to choose one when creating
a ticket). Returns every location regardless of `is_active` — the frontend is expected to
filter/gray out inactive ones when presenting a picker for *new* selections; the backend
itself only blocks inactive locations at the point a ticket tries to use one (see
`POST /ticket-new`/`PATCH /tickets/{id}` above). **Response (200):** `{"data":
[LocationResponse, ...], "msg": "Locations list fetched successfully"}`.

### `GET /locations/{location_id}`
**Who:** any authenticated user. **Response (200):** the location, wrapped. **Errors:** `404`
`"Location not found"`.

### `POST /locations`
**Who:** **Administrator only** — unlike Departments/Priorities, a Manager may not create or
edit locations. **Request body (`LocationCreate`):** `{"title": str}` (1–100 chars,
whitespace-stripped, rejected if blank). New locations are always created `is_active: true`.
**Response (201):** the created location, wrapped. **Errors:** `409` `"A location with this
title already exists"` (case-insensitive); `403` if not Administrator; `422` for a
missing/blank title.

### `PATCH /locations/{location_id}`
**Who:** Administrator only. **Request body (`LocationUpdate`):** `{"title": str | None,
"is_active": bool | None}` — both optional, partial update. **There is no `DELETE
/locations/{id}` endpoint** — retiring a location is done by `PATCH` with
`{"is_active": false}` ("deactivating" it) rather than deleting it, so tickets that already
reference it are never broken; setting `is_active: true` reactivates it. **Response (200):**
the updated location, wrapped. **Errors:** `404` not found; `409` title conflict; `403` if
not Administrator.

## Categories

All routes: `app/api/routes/categories.py`. **All responses are bare** (not wrapped in
`DataResponse`) — this is the one resource whose endpoints predate the `DataResponse`
convention and were never migrated to it.

### `GET /categories`
**Who:** any of Employee/Technician/Manager/Administrator (`_VIEW_ROLES` — effectively "any
authenticated user with one of the four roles," which in practice is every user, since those
are the only four roles that exist). **Response (bare `list[CategoryResponse]`, 200).**

### `GET /categories/{category_id}`
**Who:** same as above. **Response (bare `CategoryResponse`, 200).** **Errors:** `404`.

### `POST /categories`
**Who:** Manager or Administrator. **Request body (`CategoryCreate`):** `{"name": str
(1–100 chars), "description": str | None (≤255 chars)}`, both trimmed. **Response (bare
`CategoryResponse`, 201).** **Errors:** `409` `"A category with this name already exists"`
(case-insensitive).

### `PUT /categories/{category_id}`
**Who:** Manager or Administrator. **Request body (`CategoryUpdate`):** same shape as
`CategoryCreate` — this is a **full replacement**, not a partial patch (both `name` and
`description` must be sent every time). **Response (bare `CategoryResponse`, 200).**
**Errors:** `404`, `409`.

### `DELETE /categories/{category_id}`
**Who:** Manager or Administrator. **DB action:** `CategoryService.delete_category` first
checks `CategoryRepository.is_referenced_by_tickets(category_id)` (a `SELECT` for any
ticket with that `category_id`); if any exist, deletion is refused. **Response:** `204 No
Content`. **Errors:** `404` not found; `409` `"Cannot delete category: it is still
referenced by one or more tickets"`.

## Users

All routes: `app/api/routes/users.py`. Every response is **wrapped**. Service:
`UserService` (`app/services/user_service.py`).

### `POST /users`
**Who:** Administrator only (`require_roles("Administrator")`). **Request body
(`UserCreate`):** `username`, `first_name`, `last_name`, `email` (all required, trimmed,
rejected if blank), `department_id: int | None`, `phone_number: str | None`,
`password: str` (min 8 chars), `role_id: int` (required), `theme: str | None`.
**Validation/DB actions:** checks `username`/`email` uniqueness, validates `role_id` and
`department_id` (if given) reference real rows, hashes the password with `hash_password`,
creates the `User` row. **Response (201):** the created user, wrapped —
**never includes the password or password hash.** **Errors:** `409` duplicate
username/email; `400` `"role_id does not exist"` / `"department_id does not exist"`; `403`
if caller isn't Administrator; `401` if unauthenticated.

### `GET /users`
**Who:** Manager or Administrator. **Query params:** `role_id`, `department_id`,
`is_active`, `search` (matches username/first/last name/email, case-insensitive substring),
`skip` (default 0, ≥0), `limit` (default 100, 1–500). **Response (200):** `{"data": [...],
"msg": "Fetched N of M users"}` — `msg` reports how many rows were returned vs. how many
matched the filters in total (`UserService.list_users` returns both the page and the total
count). **Errors:** `403` if not Manager/Admin.

### `GET /users/{user_id}`
**Who:** Manager/Administrator for anyone; any other authenticated user only for their own
`id` (`UserService.get_user_for_viewer`). **Response (200):** the user, wrapped. **Errors:**
`404` not found; `403` if a non-Manager/Admin requests someone else's id.

### `PATCH /users/{user_id}`
**Who:** any authenticated user, but the *fields* allowed depend on who's calling
(`UserService.update_user` — see the Authorization section of the architecture doc for the
full split). **Request body (`UserUpdate`):** every field optional —
`username`, `first_name`, `last_name`, `email`, `department_id`, `phone_number`, `role_id`,
`is_active`, `theme`. **Never accepts a password.** **Response (200):** the updated user,
wrapped. **Errors:** `404` unknown user; `403` `UserPermissionError` (editing someone else,
or a non-admin submitting an administrative field); `409` duplicate username/email; `400`
invalid `role_id`/`department_id`.

### `PATCH /users/me/password`
**Who:** any authenticated user, always acting on their own account
(`current_user.id`, ignoring any id in the URL — there is none; the path is literally
`/users/me/password`). **Request body (`PasswordChangeRequest`):**
`{"current_password": str, "new_password": str (min 8)}`. **DB action:**
`UserService.change_own_password` verifies `current_password` against the stored hash before
setting the new one. **Response (200):** `{"data": null, "msg": "Password changed
successfully"}`. **Errors:** `400` `"Current password is incorrect"`.

### `PATCH /users/{user_id}/password`
**Who:** Administrator only. **Request body (`AdminPasswordSetRequest`):**
`{"new_password": str (min 8)}` — **no current-password check** (an intentional
admin-reset capability). **Response (200):** `{"data": null, "msg": "Password updated
successfully"}`. **Errors:** `404` unknown user; `403` if not Administrator.

## Tickets

Two routers, both in `app/api/routes/tickets.py`: `flat_router` (no `/tickets` prefix — used
only for `/ticket-new` and `/all-tickets`) and `router` (`prefix="/tickets"`, everything
else). Service: `TicketService` (`app/services/ticket_service.py`).

### `POST /ticket-new`
**Who:** Employee, Manager, or Administrator (`_CREATE_ROLES` — **Technician is
excluded**, confirmed by `tests/test_ticket_new_endpoints.py::test_ticket_new_forbidden_for_technician`).
**Request body (`TicketNewCreate`):** `title` (1–200 chars), `description` (non-empty),
`location_id: int | None`, `category_id: int`, `priority_id: int`,
`requester_user_id: int | None`. **Validation/business rules:** `category_id` and
`priority_id` must reference real rows; `location_id`, if given, must reference a real,
**active** `Location` row (a deactivated location can no longer be newly selected, though a
ticket that already has one keeps it - see the Locations section); the requester is always
the caller **unless** the caller is a Manager/Administrator *and* explicitly sets
`requester_user_id` to someone else — any other caller supplying a different
`requester_user_id` is rejected outright, before any ticket is created. **DB actions:**
generates the ticket number (§13 of the architecture doc), creates the `Ticket` row with
`status=NEW`, `assigned_technician_id=None`, writes one `ticket_created` history row,
commits. **Response (wrapped `TicketResponse`, 201)** — `location` in the response is the
full nested `LocationResponse` object (or `null`), not just an id.
**Errors:** `400` unknown/inactive category/priority/location, or unknown requester; `403`
non-Manager/Admin setting someone else as requester (or a Technician calling at all, which is
actually a 403 from the route-level role gate before the body is even parsed); `422` missing
required fields.

### `GET /all-tickets`
**Who:** any authenticated Employee/Technician/Manager/Administrator (`_VIEW_ROLES`) — but
what each of them *sees* is restricted by ownership (below). **Query params:** `status`
(`TicketStatus` enum), `priority_id`, `category_id`, `department_id` (filters by the
*requester's* department — implemented as a join through the ticket's creator, not a column
on `Ticket` itself), `requester` (aliases `created_by`), `assigned_to`, `search`
(case-insensitive substring match against title **or** description), `sort_by`
(`created_at` | `updated_at` | `title` | `ticket_number`; unrecognized values silently fall
back to `created_at`), `sort_dir` (`asc` or anything-else-means-`desc`), `skip` (default 0),
`limit` (default 100, 1–500). **Ownership enforcement:** `TicketService.list_tickets`
overwrites `requester`/`assigned_to` with the caller's own id for Employees/Technicians
respectively, regardless of what was requested — an Employee always sees only tickets they
created; a Technician always sees only tickets assigned to them; Manager/Administrator see
everything and their filters are honored as given. **Response (wrapped
`list[TicketResponse]`, 200):** `msg` is `"Fetched N tickets"`.

### `GET /tickets/{ticket_id}`
**Who:** any authenticated user who can *view* this specific ticket (via
`get_viewable_ticket`, `app/dependencies/ticket.py`) — Employee/creator, assigned
Technician, or any Manager/Administrator. **Response (bare `TicketResponse`, 200) — this one
individual-ticket endpoint is not wrapped.** **Errors:** `404` if the ticket doesn't exist;
`403` if it exists but this user cannot view it (deliberately 403, not 404, so a caller can
tell "not found" apart from "exists but not yours" — confirmed by
`TicketPermissionError`'s explicit mapping in `get_viewable_ticket`).

### `PATCH /tickets/{ticket_id}`
**Who:** any of the four roles at the route level; the actual permission is finer-grained
inside `TicketService.patch_ticket`: must first pass the same view-ownership check as `GET`;
then a Technician may always patch (if assigned); an Employee may patch **only while
`status == NEW`**; a Manager/Administrator may patch any ticket in any status. **Request
body (`TicketPatch`):** every field optional — `title`, `description`, `location_id`,
`category_id`, `priority_id`. `location_id` may explicitly be set to `null` to clear it
(unlike `category_id`/`priority_id`, which can never be null on a ticket). **Never touches
assignment, status, requester, or timestamps** — those stay in their own dedicated
endpoints/mechanisms. **DB action:** each changed field is diffed against the current value
and, if different, writes one `TicketHistory` row per field before applying the change.
**Response (wrapped `TicketResponse`, 200).** **Errors:** `404` unknown ticket; `403` not
viewable, or Employee attempting a field-forbidden edit path such as trying another user's
ticket; `409` `"This ticket can no longer be edited once work has started"` (Employee editing
a non-`NEW` ticket); `400` unknown category/priority id, or unknown/inactive location id.

### `DELETE /tickets/{ticket_id}`
**Who:** Manager or Administrator (`_DELETE_ROLES`). **DB action:** hard-deletes the
`Ticket` row; due to `cascade="all, delete-orphan"` on the model, its comments, attachments,
and history rows are deleted with it. **Response:** `204 No Content`. **Errors:** `404`.

### `PATCH /tickets/{ticket_id}/assign`
**Who:** Manager or Administrator (`_ASSIGN_ROLES`). **Request body (`TicketAssign`):**
`{"technician_id": int}`. **Validation:** rejects a closed ticket, an unknown user id, a
user whose role isn't `"Technician"`, or an inactive technician (all as `400`). **DB
action:** sets `assigned_technician_id`, writes an `assigned_technician` history row; if the
ticket's status was `NEW`, also auto-advances it to `ASSIGNED` and writes a second `status`
history row for that transition. **Response (bare `TicketResponse`, 200).** **Errors:**
`404` unknown ticket; `400` as above; `403` if not Manager/Admin.

### `PATCH /tickets/{ticket_id}/status`
**Who:** Technician, Manager, or Administrator (`_STATUS_ROLES` — **Employee excluded**).
**Request body (`TicketStatusUpdate`):** `{"status": TicketStatus}`. **Validation:** a
Technician must be the ticket's assigned technician (else `403`); the requested transition
must be legal per `_STATUS_TRANSITIONS` (else `409`). **DB action:** updates `status`; sets
`resolved_at`/`closed_at` if transitioning into `RESOLVED`/`CLOSED`; writes one `status`
history row. **Response (bare `TicketResponse`, 200).** **Errors:** `404`, `403`, `409`.

### Comments — `GET/POST /tickets/{ticket_id}/comments`, `PUT/DELETE /tickets/{ticket_id}/comments/{comment_id}`

All gated by `get_viewable_ticket` first (so "can this user see this ticket at all" is
checked once, for every comment route, before comment-specific logic runs).

- **`GET /tickets/{id}/comments`** — same viewers as the ticket itself. Bare
  `list[CommentResponse]`, ordered oldest-first.
- **`POST /tickets/{id}/comments`** — any of the four roles who can view the ticket.
  Body (`CommentCreate`): `{"content": str}` (non-empty after stripping). Bare
  `CommentResponse`, `201`. Writes a `comment_added` history row.
- **`PUT /tickets/{id}/comments/{comment_id}`** — the comment's author, or any
  Manager/Administrator (`CommentService.update_comment`); anyone else gets `403`. Body
  (`CommentUpdate`): `{"content": str}`. Sets `updated_at`. Writes a `comment_edited`
  history row (`old_value`/`new_value` = the full old/new text, truncated to 255 chars).
  Bare `CommentResponse`, `200`. `404` if the comment doesn't exist or belongs to a
  different ticket.
- **`DELETE /tickets/{id}/comments/{comment_id}`** — same author-or-manager rule. Hard
  delete. Writes a `comment_deleted` history row. `204`.

### Attachments — `app/api/routes/attachments.py`, `prefix="/tickets/{ticket_id}/attachments"`

All gated by `get_viewable_ticket`. **Unlike comments, there is no per-item ownership** —
any user who can view the ticket may upload, list, download, or delete **any** attachment on
it, including ones uploaded by someone else (stated directly in `AttachmentService`'s own
docstring).

- **`GET /tickets/{id}/attachments`** — bare `list[AttachmentResponse]`, ordered
  oldest-first. Excludes `stored_filename`/`file_path` (internal storage details are never
  exposed).
- **`POST /tickets/{id}/attachments`** — multipart `file` field (`UploadFile`). Validates:
  non-empty, ≤`MAX_ATTACHMENT_SIZE_BYTES` (10 MB default), extension in
  `{.png, .jpg, .jpeg, .pdf, .txt, .docx, .xlsx}`. Generates a random stored filename
  (UUID + validated extension), saves the bytes via `StorageService.save`, resolves
  `content_type` from the filename (not blindly trusting the client's declared
  `Content-Type` header), creates the `Attachment` row, writes an `attachment_added` history
  row. Bare `AttachmentResponse`, `201`. **Errors:** `400`
  `InvalidAttachmentError` with a specific message (empty file / oversized / unsupported
  type).
- **`GET /tickets/{id}/attachments/{attachment_id}`** — downloads the file. Loads bytes from
  disk via `StorageService.load` and returns a raw `Response` with the original filename in
  a safely-encoded `Content-Disposition` header. **Errors:** `404` if the attachment record
  doesn't exist for this ticket. **If the DB record exists but the physical file is
  missing**, `StorageService.load` raises an unhandled `FileNotFoundError` — this is **not**
  caught anywhere and would surface as an uncaught **500**, not a clean 404 (a real gap,
  documented in the architecture doc §22).
- **`DELETE /tickets/{id}/attachments/{attachment_id}`** — deletes the DB record and commits
  first, writes an `attachment_deleted` history row, **then** deletes the physical file
  (deliberate ordering — a failed physical delete leaves an orphaned file rather than a
  broken DB reference). `204`. `404` if not found.

### History — `GET /tickets/{ticket_id}/history`

Gated by `get_viewable_ticket` — same visibility as the ticket itself, read-only. Bare
`list[TicketHistoryResponse]`, ordered oldest-first. Each entry: `action` (from the model's
`field_name`), `performed_by` (a `TicketUserSummary`), `old_value`, `new_value`, `timestamp`
(from `created_at`).
